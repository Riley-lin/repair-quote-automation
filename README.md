# 維修報價每日自動化系統

**RPA + Python｜客服維修報價流程自動化**

> ⚠️ 本專案為公司內部實際使用的工具，基於資安考量，僅提供架構與設計說明，不公開程式碼與資料。
> 

---

## 📌 背景與痛點

在客服部門，每天都要處理經銷商送修產品的報價與檢測通知。原本的流程完全手動：

1. 登入內部維修系統，手動設定日期區間、勾選多個匯出欄位
2. 匯出 Excel，篩出「待報價」的案件
3. 逐筆判斷是「報價單」、「檢測通知」還是「整新」
4. 把資料一筆筆複製貼上到不同的 Excel 報價範本
5. 存檔到公用資料夾
6. 撰寫 Email，把資料整理成表格貼進內文、附上報價單後寄出

每天重複、步驟多、容易貼錯欄位，而且熟悉流程的人一請假就沒人能接手。

## 🎯 解決方案

把流程拆成**兩段自動化**，透過一個共用資料夾交接：

```
┌──────────────────────────┐        ┌──────────────────────────────┐
│ 流程一：資料擷取 (RPA)    │        │ 流程二：資料處理與通知 (Python) │
│                          │        │                              │
│ 內部維修系統網頁          │        │ 讀取最新匯出檔                 │
│   ↓ 自動設定條件並匯出     │  ───▶  │   ↓ 規則分類                   │
│ Excel 匯出檔              │  資料夾 │   ↓ 自動填入報價範本            │
│   ↓ 自動搬移歸檔          │  交接   │   ↓ 存檔（含失敗備援）          │
│                          │        │   ↓ 產生 Outlook 草稿待審核     │
└──────────────────────────┘        └──────────────────────────────┘
```

**為什麼要拆成兩段？** 兩段流程彼此獨立。網頁匯出失敗，還能用前一份資料繼續處理；處理端出錯，也不用重新匯出，除錯比較容易。

## 🛠 使用技術

| 類別 | 工具 |
| --- | --- |
| RPA | Power Automate Desktop |
| 網頁自動化 | Chrome + JavaScript（直接操作 DOM） |
| 資料處理 | Python 3、openpyxl、正規表達式 |
| Office 整合 | Outlook COM 自動化（pywin32）、Excel 範本 |
| 執行與維運 | Windows Batch 一鍵執行、執行紀錄 log |

## ⚙️ 功能說明

### 流程一：自動匯出

- 自動開啟系統頁面，動態計算「今天往前一個月」的日期區間
- 用 JavaScript 一次完成多個欄位的勾選與排序，找不到欄位時會自動重試
- 偵測下載資料夾，新檔案一出現就繼續，不用固定空等
- 自動把匯出檔搬到指定資料夾

### 流程二：分類、填表、通知

- **自動分類**：依單號規則和備註內容，把案件分成「報價單 / 檢測通知 / 整新」三類
- **金額解析**：從自由輸入的備註文字（例如「品項A＋品項B＝XXX＋YYY」這種格式）拆出維修品項與金額，對應到範本的品項列
- **範本填寫**：每筆報價產生一張報價表，檢測通知依實際筆數動態重建公式，用不到的列自動隱藏
- **存檔備援**：網路磁碟寫入失敗時，自動改存本機並記錄原因
- **Email 草稿**：自動產生 HTML 表格內文、套用公司簽名檔、附上報價單，**只開草稿、不自動寄出**，由人工確認後才送出

## 🧩 解決的技術挑戰

| 問題 | 解法 |
| --- | --- |
| 錄製的 RPA 操作日期選擇器時會卡住 | 改用 JavaScript 直接寫入日期欄位的值，繞過日曆彈窗 |
| 固定等待下載時間，太短會失敗、太長浪費時間 | 先記錄匯出前已有的檔案，之後每秒比對，新檔一出現就繼續，最多等待數十秒 |
| 備註格式不統一（有分項金額、只有總價、多個非標準品項） | 設計多種解析模式；範本沒有的品項借用空的列改名填入，避免資料遺漏 |
| 網路磁碟偶爾無法存取 | 建立 fallback 機制改存本機，並寫 log 方便事後追查 |
| 使用者電腦沒有管理員權限、環境不一 | Batch 自動偵測 Python，套件裝在專案資料夾內，不需要管理員權限 |
| 自動寄錯信的風險 | 採用「人在迴路中」設計：系統只準備草稿，最後一步由人確認 |

## 🔒 資安設計原則

- 所有資料只在本機和公司內網處理，**不上傳任何雲端服務**
- 帳號密碼不寫死在程式裡
- 郵件一律經人工審核後才寄出

## 📈 成效

- 已於日常作業中每日實際上線使用並穩定運作
- 原本需要逐筆複製貼上的作業，縮短為「執行 → 審核草稿 → 寄出」
- 流程標準化，非原負責人也能照著執行
